Аутентификация vs авторизация

Аутентификация

«Кто ты?»

Подтверждение личности.

Логин + пароль, отпечаток, Face ID

Авторизация

«Что тебе можно?»

Проверка прав после входа.

Доступ к папке, право удалять, роль админа

Порядок: сначала аутентификация, потом авторизация. Нельзя дать права тому, кого не опознали.

Аналогия: паспортный контроль (кто ты) → пропуск в конкретные двери (что можно).

Три фактора аутентификации

1

Знание

Что ты знаешь.

Пароль, PIN, секретный вопрос

2

Владение

Что у тебя есть.

Телефон (SMS/TOTP), аппаратный ключ, карта

3

Биометрия

Кто ты есть.

Отпечаток, лицо, голос

MFA — два и более разных фактора. Пароль + SMS — MFA. Два пароля — нет (оба — знание).

Энтропия пароля

Энтропия — мера сложности подбора, в битах. Чем больше — тем лучше.

Энтропия ≈ длина × log₂(размер алфавита)
ПарольАлфавитДлинаЭнтропияОценка
12345610 цифр6~20 битслабо
qwerty26 букв6~28 битслабо
Tr0ub4dor&3~7211~65 битнорм
correct horse battery staple26+пробел28~130 битотлично
Вывод: длина важнее сложности. Длинная фраза из слов надёжнее короткого «сложного» пароля.

Хеширование паролей

Хеш — необратимое преобразование: из пароля получают «отпечаток», из отпечатка пароль не восстановить.

пароль → [хеш-функция] → хеш

Как хранят на сервере

  1. Регистрация: хеш = hash(пароль + соль) → сохраняют только хеш
  2. Вход: hash(введённый + соль) → сравнивают с сохранённым

Соль

Случайная строка перед хешированием. Одинаковые пароли → разные хеши. Защита от «радужных таблиц».

Не хранить в открытом виде: при утечке БД злоумышленник получит все пароли сразу. С хешами — «отпечатки», которые дорого подбирать.

Медленные хеши для паролей: bcrypt, scrypt, Argon2. Не MD5/SHA-1 — они быстрые.

Менеджеры паролей

Что делают

  • Хранят пароли в зашифрованном виде
  • Генерируют уникальные длинные пароли
  • Нужно помнить один мастер-пароль (длинный!)

Примеры

  • Bitwarden
  • KeePass
  • 1Password
Базовый минимум: менеджер паролей + 2FA.

Управление доступом

Авторизация решает, что можно после входа.

RBAC

Права по ролям.

«Админ», «менеджер», «гость»

ABAC

Права по атрибутам.

«Отдел = X и время < 18:00»

MAC

Жёсткие метки.

«Секретно», «ДСП»

RBAC — самый распространённый: сотруднику дают роль, роль имеет права. Не «права на каждого», а «роль → права».

Минимум привилегий и default deny

Минимум привилегий

Давать только необходимые права. Нужен отчёт — доступ к отчёту, а не ко всей базе.

Если аккаунт взломают — ущерб ограничен его правами.

Default deny

По умолчанию всё закрыто, открывается только нужное.

Безопаснее, чем «разрешить всё, потом запретить лишнее».

Практика: оценка энтропии

Оцените сложность паролей (приблизительно, по формуле):

1. 123456
2. Summer2024!
3. correct horse battery staple
1 — ~20 бит (слабо). 2 — ~50 бит (средне, но предсказуемо: сезон + год + «!»). 3 — ~130 бит (отлично: длина решает).

Ситуация: бухгалтер, менеджер, админ БД, директор. Системы: 1С, CRM, БД, почта.
