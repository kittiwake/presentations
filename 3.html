Сетевые угрозы

Sniffing

Пассивный перехват трафика.

Wireshark, tcpdump. Защита: TLS, VPN.

MITM

Атакующий между клиентом и сервером.

Читает и меняет. Защита: сертификаты, HSTS, VPN.

DDoS

Массовая перегрузка сервера.

Ботнет. Защита: CDN, rate limiting.

ARP-spoofing

Подмена ARP: «шлюз — это я».

Трафик через атакующего. Защита: DAI, статические ARP.

Evil twin

Фальшивая точка доступа с тем же именем.

Защита: проверять сертификаты, VPN.

Общая защита

HTTPS, VPN, firewall, проверка сертификатов.

Sniffing и MITM

Sniffing (прослушивание)

  • Пассивный перехват в той же сети
  • Без шифрования видны пароли, cookies
  • Инструменты: Wireshark, tcpdump
  • Защита: HTTPS/TLS, VPN

MITM (человек посередине)

  • Атакующий между клиентом и сервером
  • Может читать и менять трафик
  • Способы: evil twin, ARP-spoofing, подмена сертификата
  • Защита: проверка сертификатов, HSTS, VPN
Аналогия: sniffing — кто-то слушает ваш разговор; MITM — кто-то представляется вашим собеседником.

HTTPS/TLS: что даёт

TLS — шифрование поверх TCP. HTTPS = HTTP + TLS.

Конфиденциальность

Симметричное шифрование (AES) — содержимое не прочитать.

Аутентификация

Сертификат от CA подтверждает, что сервер — тот, за кого себя выдаёт.

Целостность

MAC/подпись — изменение пакета обнаруживается.

Даже в открытом Wi-Fi содержимое защищено. Но метаданные (какие сайты) видны, и фишинг возможен — проверяйте домен.

TLS-handshake (упрощённо)

1. ClientHello — версии, шифры, случайное число
2. ServerHello — выбранный шифр + сертификат
3. Проверка сертификата — CA, срок, домен
4. Согласование ключей — ECDHE → общий секрет
5. Шифрованная сессия — симметричное шифрование
Клиент → ClientHello → Сервер
Клиент ← ServerHello + сертификат ← Сервер
Клиент: проверка сертификата
Клиент ↔ согласование ключей (ECDHE) ↔ Сервер
Клиент ↔ шифрованная сессия (AES) ↔ Сервер

Сертификат: что внутри

ПолеЧто значит
SubjectКому выдан (домен, например example.com)
IssuerКем выдан (CA: Let's Encrypt, DigiCert)
Not Before / Not AfterСрок действия
Публичный ключДля проверки подписи
SANСписок доменов, на которые действует
Сертификат подписан CA. Браузер доверяет CA из встроенного списка. Самоподписанный → предупреждение.

HSTS (HTTP Strict Transport Security)

Заголовок, который заставляет браузер использовать только HTTPS для домена.

Strict-Transport-Security: max-age=31536000; includeSubDomains

Зачем

  • Защита от SSL-stripping (MITM подменяет HTTPS на HTTP)
  • Браузер запоминает HSTS и не даёт перейти на HTTP

Проверка

curl -sI https://example.com | grep -i strict-transport

VPN

VPN — шифрованный туннель между устройством и VPN-сервером.

Зачем

  • Защита в открытом Wi-Fi
  • Скрыть содержимое от провайдера
  • Сменить видимый IP
  • Корпоративный доступ

Протоколы

  • WireGuard (современный)
  • OpenVPN
  • IPsec
VPN не заменяет HTTPS. Он защищает канал, но если сайт по HTTP — внутри туннеля всё равно открытый текст.

Firewall

Фильтр трафика по правилам (IP, порт, протокол, содержимое).

ТипУровеньЧто делает
Пакетный фильтр3–4IP/порт/протокол каждого пакета
Stateful3–4Помнит таблицу соединений
NGFW3–7Анализ приложений, URL, IPS
Default deny: по умолчанию всё запрещено, открывается только нужное.
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22/tcp
sudo ufw allow 443/tcp
sudo ufw enable

Сегментация сети (VLAN)

Что это

Разделение сети на изолированные сегменты: гости, сотрудники, серверы, принтеры.

Зачем

Если один сегмент взломали — остальные изолированы. Гостевой Wi-Fi не видит серверы.

Аналогия: отдельные комнаты с замками в одном здании — пожар в одной не перекинется на другие.

Wi-Fi: WPA2 vs WPA3

WPA2WPA3
ШифрованиеAES-CCMPAES-GCMP
Защита от подбораУязвим (offline-подбор)SAE (защита от offline)
СтатусУстареваетСовременный стандарт
WPS — отключить. Уязвим к подбору PIN (Pixie Dust). Кнопка WPS на роутере — риск.

Evil twin и защита Wi-Fi

Evil twin

  • Фальшивая точка с тем же именем
  • Не спрашивает пароль (открытая)
  • Сертификат сайта не совпадает

Защита

  • Проверять сертификаты
  • VPN в открытых сетях
  • Не подключаться к «знакомым» открытым сетям
DHCP snooping — защита от rogue DHCP. Port security — ограничение MAC на порту. Гостевая сеть — отдельный VLAN.

Практика

1. Сертификат

openssl s_client -connect example.com:443 -servername example.com

2. HSTS

curl -sI https://example.com | grep -i strict-transport

3. Firewall (Linux)

sudo ufw default deny incoming
sudo ufw allow 22/tcp
sudo ufw allow 443/tcp
sudo ufw enable

4. Wi-Fi

Проверьте тип безопасности (WPA2/WPA3), отключён ли WPS, есть ли гостевая сеть.
